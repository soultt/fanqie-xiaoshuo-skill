## 阻塞式执行机制（强制）

**每个阶段必须完成才能进入下一个阶段，不可跳过任何阶段。**

### 执行规则

- **规则1**：必须按顺序执行，不可跳过任何阶段
- **规则2**：每个阶段必须输出完成确认
- **规则3**：子技能调用失败 → 强制阻塞，必须修复后重试
- **规则4**：每个阶段完成后必须勾选确认，才能进入下一阶段
- **规则5**：最终输出必须包含所有阶段的完成确认

### 节点完成确认清单

**每完成一个阶段，必须勾选确认**：
- [ ] **节点0**：阶段零确认（阻塞式执行机制已启用）
- [ ] **节点1**：阶段一（项目初始化）已完成
- [ ] **节点2**：阶段二（设定设计）已完成
- [ ] **节点3**：阶段三（大纲设计）已完成
- [ ] **节点4**：阶段四（大纲审查）已完成
- [ ] **节点5**：阶段五（章纲创建）已完成
- [ ] **节点6**：阶段六（章纲审查与修复）已完成
- [ ] **节点7**：阶段七（正文写作）已完成
- [ ] **节点8**：阶段八（正文审查与修复）已完成
- [ ] **节点9**：阶段九（签约评估）已完成

**未全部勾选 → 写作流程未完成，不得输出完成声明**

### 阻塞触发条件

> **阻塞说明（强制）**：所有触发条件均为强制阻塞，不得以任何理由跳过。

| 触发条件        | 阻塞级别    | 处理方式         |
| ----------- | ------- | ------------ |
| 任一阶段执行失败 | 强制阻塞 | 立即停止，修复后重试   |
| 子技能调用失败   | 强制阻塞 | 立即停止，检查子技能状态 |
| 审查发现严重问题 | 强制阻塞 | 立即停止，修复后重新审查 |
| 任何阶段未执行   | 强制阻塞 | 补全后才能输出完成声明  |

目标：4200非空白字符/天，分解：2章 × 2100字符/章（首秀期提升至6000字/天）

### 流程三：批量处理自动化
由 `flow-automation` 技能调度执行，支持批量章纲创建和批量正文写作

## 番茄小说平台优化规则

### 签约标准适配

#### 三次机会制度

| 字数节点 | 签约机会  | 失败后处理         |
| ---- | ----- | ------------- |
| 2万字  | 第一次申请 | 修改作品，继续更新至5万字 |
| 5万字  | 第二次申请 | 修改作品，继续更新至8万字 |
| 8万字  | 第三次申请 | 失败则永久失去签约资格   |

#### 开篇黄金三章

- **第一章**：开头500字内出现强冲突，立即建立代入感
- **第二章**：给出金手指或反转线索，展示主角潜力，埋下第一个伏笔
- **第三章**：打出第一个小高潮（反派打脸/身份暴露/实力展现），完成情绪绑架

#### 节奏控制标准

- 每章约2100非空白字符（约2000字正文体量）
- 每500字出现一次小转折
- 每章结尾卡在"刚要爽就断"的悬念点
- 避免连续3段以上纯心理描写或背景交代
- 对话不超过5轮不推进剧情

#### 2025年新增审核重点

1. 情节套路化特征显著的内容
2. 叙事逻辑混乱的作品
3. 大篇幅使用AI生成的低质内容
4. 结构混乱、转折生硬、逻辑割裂的内容

## 核心原则

### 创作原则
1. **大纲为王**：一切创作以大纲为基准，不得超纲
2. **章纲约束**：正文必须完全符合章纲规划
3. **质量优先**：审查不通过不进入下一阶段
4. **数据驱动**：以番茄小说平台数据指标为导向

### 审查原则
1. **优先审查**：前后章节冲突必须首先解决
2. **分级处理**：严重问题必须修复，中等问题建议修复
3. **迭代优化**：修复后重新审查，确保问题解决
4. **字数达标**：正文非空白字符≥2100为硬性指标

### 自动化原则
1. **约束先行**：创作前必须读取约束条件
2. **过程监控**：实时追踪进度和质量
3. **异常处理**：发现问题自动修复
4. **结果验证**：输出前验证符合性
