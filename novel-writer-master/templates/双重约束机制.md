# 双重约束机制

> 本文件由 `novel-writer-master/SKILL.md` 引用，定义创作过程中的强制约束机制。

---

## 双重约束机制（强制）

```
双重约束机制（强制）：大纲 → 章纲 → 正文

第一层：大纲约束章纲
├── 章纲必须完全符合大纲
├── 章纲不得超出大纲范围
└── 大纲符合率 = 100%

第二层：章纲约束正文
├── 正文必须完全符合章纲
├── 正文不得超出章纲范围
└── 章纲符合率 = 100%

约束链：
大纲（总纲+卷纲）→ 章纲 → 正文
    ↓               ↓        ↓
  100%           100%      100%
  
任何一层不符合 = 必须修复
```

---

## 大纲约束强制规则

```
1. 章纲创建前必须读取大纲约束
   ├── 必须读取总纲
   ├── 必须读取卷纲
   └── 必须读取人物设定（由 novel-setting-designer 创建）

2. 章纲内容必须在大纲范围内
   ├── 禁止添加大纲未规划的人物
   ├── 禁止添加大纲未规划的事件
   ├── 禁止添加大纲未规划的地点
   ├── 禁止添加大纲未规划的能力
   └── 禁止添加大纲未规划的物品

3. 章纲任务必须来自卷纲分配
   ├── 本章任务 = 卷纲分配的任务
   ├── 主线推进 = 卷纲规划的推进
   └── 爽点设计 = 卷纲规划的爽点

4. 章纲审查必须检查大纲符合性
   ├── 超出大纲 → 必须删除
   ├── 遗漏大纲 → 必须补充
   └── 偏离大纲 → 必须调整
```

---

## 章纲约束强制规则

```
1. 正文创作前必须读取章纲约束
   ├── 必须读取本章章纲
   ├── 必须读取人物设定（由 novel-setting-designer 创建）
   └── 必须读取前章正文（如有）

2. 正文内容必须在章纲范围内
   ├── 禁止添加章纲未规划的人物
   ├── 禁止添加章纲未规划的事件
   ├── 禁止添加章纲未规划的对话
   ├── 禁止添加章纲未规划的场景
   └── 禁止添加章纲未规划的情节

3. 正文情节必须来自章纲规划
   ├── 四部分结构 = 章纲规划的结构
   ├── 情节发展 = 章纲规划的情节
   ├── 卡点设计 = 章纲规划的卡点
   └── 爽点设计 = 章纲规划的爽点

4. 正文审查必须检查章纲符合性
   ├── 超出章纲 → 必须删除
   ├── 遗漏章纲 → 必须补充
   └── 偏离章纲 → 必须调整
```

## 异常处理机制

> 以上异常处理规则是「双重约束机制」的实操细化。

| 异常类型          | 处理方式                                  |
| ------------- | ------------------------------------- |
| 章纲缺失          | 自动调用 novel-chapter-outline-creator 创建 |
| 正文缺失          | 自动调用 novel-chapter-writer 创建          |
| 章纲审查不通过       | 自动分析问题优先级，执行修复流程                      |
| 正文审查不通过       | 自动分析问题优先级，执行修复流程                      |
| 严重问题未修复       | 阻止进入下一阶段，强制修复                         |
| 字数不足（<2100字符） | 自动扩展描写，增加细节                           |
| 字数过多（>3000字符） | 自动精简冗余内容                              |
| 正文超纲          | 删除超纲内容，强制回归章纲                         |
| 正文遗漏章纲        | 补充遗漏的章纲要求                             |
| 正文偏离章纲        | 调整正文方向，回归章纲规划                         |
| 章纲超纲          | 删除超纲内容，强制回归大纲                         |
| 章纲遗漏大纲        | 补充遗漏的大纲要求                             |
| 章纲偏离大纲        | 调整章纲方向，回归大纲规划                         |
| 前后冲突          | 标记冲突位置，自动生成修复方案并执行                    |
| 修复引入新问题       | 回滚修复，重新制定修复方案                         |
| 修复验证失败        | 重新审查，迭代修复直至通过                         |
| 人设崩塌          | 强制修复，调整人物行为描写                         |
