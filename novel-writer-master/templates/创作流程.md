# 创作流程定义

> 本文件由 `novel-writer-master/SKILL.md` 引用，定义完整创作流程的详细执行步骤。

---

## 流程一：完整创作流程（新项目启动）

> **职责说明**：完整创作流程的具体步骤由 `novel-creation-workflow` 技能负责编排和执行，本技能负责调度和异常处理。

```
┌─────────────────────────────────────────────────────────────────┐
│                    完整创作流程自动化                              │
└─────────────────────────────────────────────────────────────────┘

阶段一：项目初始化
├── 创建项目目录结构
├── 确认创作参数（题材、字数、风格）
└── 输出：项目框架

**节点完成确认**：[ ] 节点1：阶段一（项目初始化）已完成

阶段二：设定设计
├── 调用 novel-setting-designer
├── 创建 03-人物设定/主角.md、配角.md、反派.md
├── 创建 04-世界观/力量体系.md、势力分布.md、地理设定.md、时间线.md、物品装备.md
├── 设计核心冲突与反派生长
└── 输出：完整设定体系

**节点完成确认**：[ ] 节点2：阶段二（设定设计）已完成

阶段三：大纲设计
├── 调用 novel-outline-designer
├── 创建 01-总纲/总纲.md
├── 创建 02-卷纲/NN-第X卷-卷名.md
└── 输出：完整大纲体系

**节点完成确认**：[ ] 节点3：阶段三（大纲设计）已完成

阶段四：大纲审查
├── 调用 novel-master-outline-vetter
├── 审查总纲质量（核心钩子、主角设定、主线脉络）
├── 审查卷纲质量（卷任务、情节结构、爽点节奏）
├── 审查逻辑一致性（总纲与卷纲、卷纲与卷纲）
├── 审查签约标准（开篇吸引力、节奏把控）
├── 生成审查报告：07-审查报告/大纲审查/
├── 分析问题优先级
├── 执行修复（严重问题必须修复）
└── 输出：审查通过的大纲

**节点完成确认**：[ ] 节点4：阶段四（大纲审查）已完成

阶段五：章纲创建（循环）
├── 5.1 大纲约束检查
│     ├── 读取总纲、卷纲、人物设定
│     ├── 提取大纲约束条件
│     └── 生成大纲约束清单
├── 5.2 调用 novel-chapter-outline-creator
│     ├── 严格按大纲约束创建章纲
│     └── 禁止添加大纲未规划的内容
├── 5.3 创建 05-章纲/NN-第X卷-卷名/第XXX章-xxx.md
└── 重复直至完成本卷所有章纲

**节点完成确认**：[ ] 节点5：阶段五（章纲创建）已完成

阶段六：章纲审查与修复（循环）
├── 调用 novel-outline-vetter
├── 审查大纲符合性（超出/遗漏/偏离）
├── 审查结构完整性（四部分、字数分配）
├── 审查剧情质量（卡点、爽点、伏笔）
├── 审查文笔规范（对话占比、段落长度）
├── 生成审查报告：07-审查报告/章纲审查/
├── 分析问题优先级
├── 执行修复（严重问题必须修复）
└── 更新章纲文件

**节点完成确认**：[ ] 节点6：阶段六（章纲审查与修复）已完成

阶段七：正文写作（循环）
├── 7.1 章纲约束检查
│     ├── 读取章纲、人物设定、前章正文
│     ├── 提取章纲约束条件
│     └── 生成章纲约束清单
├── 7.2 调用 novel-chapter-writer
│     ├── 严格按章纲约束创作正文
│     ├── 扩展：250-350非空白字符章纲 → 2100+非空白字符正文
│     └── 禁止添加章纲未规划的内容
└── 7.3 创建 06-正文/NN-第X卷-卷名/第XXX章-xxx.md

**节点完成确认**：[ ] 节点7：阶段七（正文写作）已完成

阶段八：正文审查与修复（循环）
├── 调用 novel-chapter-vetter
├── 优先审查：前后章节冲突（7项）
├── 一级审查：章纲符合性
├── 二级审查：章节连贯性
├── 三级审查：人设一致性
├── 四级审查：结构符合性
├── 五级审查：内容质量
├── 六级审查：文笔规范
├── 生成审查报告：07-审查报告/正文审查/
├── 分析问题优先级
├── 执行修复（严重问题必须修复）
├── 验证字数达标（≥2100非空白字符）
└── 更新正文文件

**节点完成确认**：[ ] 节点8：阶段八（正文审查与修复）已完成

阶段九：签约评估
├── 调用 fanqie-contract-evaluator
├── 评估签约可行性（2万/5万/8万字节点）
├── 检查开篇质量（前3章专项审查）
├── 检查数据指标（书架比、追更比）
└── 输出签约评估报告

**节点完成确认**：[ ] 节点9：阶段九（签约评估）已完成
```

## 流程二：日更自动化（每日写作）

```
┌─────────────────────────────────────────────────────────────────┐
│                    日更自动化流程                                 │
│                 目标：4200非空白字符/天                           │
│                 分解：2章 × 2100字符/章                           │
└─────────────────────────────────────────────────────────────────┘

**首秀期特殊要求（强制）**：日更6000字（约6300非空白字符，番茄平台首秀期标准，与日常4200非空白字符标准不同）。
> 首秀期指作品进入番茄推荐首秀阶段（详见统一标准.md 5.5.3节），期间需将日更目标提升至6000字/天。

每章执行流程：
┌─────────────────────────────────────────────────────────────────┐
│ 步骤1：章纲创建（含大纲约束）                                     │
│ ├── 读取大纲约束（总纲+卷纲+人物设定）                            │
│ ├── 调用 novel-chapter-outline-creator                          │
│ └── 输出：05-章纲/NN-第X卷-卷名/第XXX章-xxx.md                   │
├─────────────────────────────────────────────────────────────────┤
│ 步骤2：章纲审查与修复                                            │
│ ├── 调用 novel-outline-vetter                                   │
│ ├── 审查大纲符合性、结构完整性、剧情质量                          │
│ ├── 生成审查报告                                                 │
│ ├── 执行修复（严重问题必须修复）                                  │
│ └── 更新章纲文件                                                 │
├─────────────────────────────────────────────────────────────────┤
│ 步骤3：正文写作（含章纲约束）                                     │
│ ├── 读取章纲约束（章纲+人物设定+前章正文）                        │
│ ├── 调用 novel-chapter-writer                                   │
│ └── 输出：06-正文/NN-第X卷-卷名/第XXX章-xxx.md                   │
├─────────────────────────────────────────────────────────────────┤
│ 步骤4：正文审查与修复                                            │
│ ├── 调用 novel-chapter-vetter                                   │
│ ├── 执行六级审查                                                 │
│ ├── 生成审查报告                                                 │
│ ├── 执行修复（严重问题必须修复）                                  │
│ ├── 验证字数达标（≥2100非空白字符）                              │
│ └── 更新正文文件                                                 │
└─────────────────────────────────────────────────────────────────┘

日更统计：
├── 已写章节：2章
├── 非空白字符：≥4200字符
└── 目标完成率：100%
```

## 流程三：批量处理自动化

> **职责说明**：批量处理流程由 `flow-automation` 技能调度执行，实现自动化批量创建、审查和写作。

```
┌─────────────────────────────────────────────────────────────────┐
│                    批量章纲创建                                   │
└─────────────────────────────────────────────────────────────────┘

触发条件：用户请求"批量创建章纲"或"规划第X章到第Y章"

执行步骤：
├── 阶段一：大纲约束准备
│     ├── 读取总纲、卷纲、人物设定
│     └── 生成大纲约束清单（按章节）
├── 阶段二：循环创建章纲
│     ├── 读取本章大纲约束
│     ├── 调用 novel-chapter-outline-creator
│     ├── 创建章纲文件
│     └── 继续下一章
├── 阶段三：批量大纲符合性检查
│     ├── 检查是否超出/遗漏/偏离大纲
│     ├── 发现问题立即修复
│     └── 更新问题章纲
└── 阶段四：输出批量创建报告

┌─────────────────────────────────────────────────────────────────┐
│                    批量正文写作                                   │
└─────────────────────────────────────────────────────────────────┘

触发条件：用户请求"批量写正文"或"写第X章到第Y章"

执行步骤：
├── 阶段一：章纲约束准备
│     ├── 读取章纲文件列表
│     └── 生成章纲约束清单（按章节）
├── 阶段二：循环写作正文
│     ├── 读取本章章纲约束
│     ├── 读取前章正文（如有）
│     ├── 调用 novel-chapter-writer
│     ├── 创建正文文件
│     └── 继续下一章
├── 阶段三：批量章纲符合性检查
│     ├── 检查是否超出/遗漏/偏离章纲
│     ├── 发现问题立即修复
│     └── 更新问题正文
├── 阶段四：批量审查
│     ├── 调用 novel-chapter-vetter
│     └── 输出审查报告
└── 阶段五：输出批量写作报告
```

## 使用示例

### 示例1：启动新项目

```
User: "开始创作新小说《九霄神帝》，玄幻题材，预计100万字"

执行流程：
1. 创建项目目录结构
2. 调用 novel-setting-designer 设计设定体系
3. 调用 novel-outline-designer 设计大纲
4. 调用 novel-master-outline-vetter 审查大纲
5. 等待用户确认后继续...
```

### 示例2：日更写作

```
User: "今天写第51章和第52章"

执行流程：
1. 检查章纲是否存在
2. 调用 novel-chapter-writer 写第51章
3. 调用 novel-chapter-vetter 审查第51章
4. 调用 novel-chapter-writer 写第52章
5. 调用 novel-chapter-vetter 审查第52章
6. 输出日更报告
```

### 示例3：批量处理

```
User: "批量创建第一卷所有章纲（1-100章）"

执行流程：
1. 读取总纲和第一卷卷纲
2. 循环调用 novel-chapter-outline-creator
3. 输出批量创建报告
```

### 示例4：签约评估

```
User: "评估我的作品能否签约"

执行流程：
1. 调用 fanqie-contract-evaluator
2. 检查开篇黄金三章
3. 检查数据指标
4. 输出签约评估报告
```

### 示例5：审查修复

```
User: "审查并修复第15章正文"

执行流程：
1. 调用 novel-chapter-vetter 审查正文
2. 生成审查报告
3. 分析问题优先级
4. 执行修复（严重问题必须修复）
5. 验证修复结果
6. 更新正文文件和审查报告
7. 输出修复摘要
```
