# 小说创作统一标准规范

> **重要说明（强制）**：本文件是所有技能的唯一标准来源。任何技能不得在本文件外定义标准值。
> 如发现技能内部硬编码的数值与本文件冲突，以本文件为准。
> 所有标准值均从以下技能中提取验证：novel-writer-master、novel-chapter-outline-creator、novel-chapter-writer、novel-outline-vetter、novel-chapter-vetter、novel-master-outline-vetter、fanqie-contract-evaluator、flow-automation。

## 一、字数标准

### 1.1 日更目标
- **日更标准**：4200非空白字符/天
- **分解**：2章 × 2100非空白字符/章
- **来源**：novel-writer-master、novel-chapter-writer、flow-automation

### 1.2 每章字数
- **正文目标**：≥2100非空白字符
- **字数达标率**：≥98%
- **字数过多阈值**：>3000字符建议精简
- **来源**：novel-writer-master、novel-chapter-writer、novel-outline-vetter、novel-chapter-vetter、fanqie-contract-evaluator、flow-automation

### 1.3 四部分结构字数分配

| 部分 | 标准值（章纲） | 标准值（正文） | 范围 |
|------|---------------|---------------|------|
| 开头钩子 | 250字符 | 约250字符 | 200-300字符 |
| 剧情发展 | 650字符 | 约650字符 | 600-700字符 |
| 情绪高潮 | 600字符 | 约600字符 | 500-700字符 |
| 章节卡点 | 400字符 | 约400字符 | 350-450字符 |
| **总计** | **1900字符** | **约1900字符** | **1700-2100字符** |

> 正文写作目标≥2100非空白字符，通过细节描写扩展。
> **来源**：novel-chapter-outline-creator、novel-chapter-writer、novel-outline-vetter、novel-chapter-vetter

### 1.4 字数统计规则
```python
# 标准统计方法
non_space_chars = len([c for c in content if not c.isspace()])
# 包含：汉字、标点符号、英文字母、数字、特殊符号等所有非空白字符
# 不包含：空格、换行符、制表符等空白字符
```
> **来源**：novel-chapter-outline-creator、novel-chapter-writer、novel-outline-vetter、novel-chapter-vetter

### 1.6 AI辅助写作规范

### 1.6.1 AI使用声明要求

根据《人工智能生成合成内容标识办法》（2025年9月1日起施行）：

| 使用场景 | 标识要求 | 平台后果 |
|---------|---------|---------|
| **使用AI生成内容** | 必须如实勾选"使用AI" | 可能限流、签约率降低至0.8% |
| **未标识但实际使用AI** | 违规 | 审核不通过、降权处罚 |
| **AI辅助+人工深度修改** | 建议标识，但需确保去AI化 | 相对安全，取决于最终质量 |
| **纯人工创作** | 无需标识 | 正常推荐、签约率约3% |

### 1.6.2 AI味特征识别（必须避免）

**以下特征是平台AI检测系统的识别点**：

| 特征类别 | 具体表现 | 检测风险 |
|---------|---------|---------|
| **人物关系混乱** | 前后矛盾、性格突变、关系错乱 | 高 |
| **修饰过度** | 堆砌形容词、不推进情节 | 高 |
| **乱加戏** | 无关情节、人设走偏 | 高 |
| **时间感缺失** | 缺乏时间推移、场景跳跃突兀 | 高 |
| **结尾强加心理** | 莫名其妙的心理描写、情绪转折生硬 | 高 |
| **开头堆数字** | 精密数字、专业名词堆砌（DeepSeek常见） | 高 |
| **对话不自然** | 过于书面化、缺乏口语特征 | 中 |
| **情节套路化** | 固定模板、缺乏创新 | 中 |
| **情感表达空洞** | 形容词堆砌、无具体行为支撑 | 中 |

### 1.6.3 去AI化核心原则

**目标**：让AI生成的内容看起来像人工创作

| 原则 | 说明 |
|------|------|
| **增加具体细节** | 用具体动作、场景替代抽象描述 |
| **强化人物个性** | 给角色添加独特口癖、习惯动作 |
| **打破完美节奏** | 适当加入意外、停顿、打断 |
| **注入情感波动** | 情绪变化要有层次，不要一步到位 |
| **添加时间标记** | 明确时间流逝、场景转换 |
| **口语化处理** | 对话要口语化，避免书面语 |

### 1.6.4 去AI化改写流程

```
AI生成初稿
    ↓
第一步：删除过度修饰
    - 删除堆砌的形容词
    - 删除不推进情节的描写
    ↓
第二步：修正人物一致性
    - 检查人物性格是否前后一致
    - 检查人物关系是否清晰
    ↓
第三步：添加具体时间感
    - 添加时间推移标记
    - 添加场景转换过渡
    ↓
第四步：优化对话自然度
    - 改为口语化表达
    - 添加语气词、停顿
    ↓
第五步：注入情感层次
    - 情绪变化分层次展现
    - 用行为体现情绪，而非直接描述
    ↓
第六步：添加个性化细节
    - 添加角色独特习惯
    - 添加意外、打断等不完美元素
    ↓
最终检查：AI味检测
    - 逐条对照1.6.2检查
    - 通过后再输出
```

### 1.6.5 AI辅助写作建议

| 使用方式 | 风险等级 | 建议 |
|---------|---------|------|
| **纯AI生成，一键发布** | 高风险 | 不建议，易被限流、签约率低 |
| **AI生成+轻度修改** | 中风险 | 需深度去AI化，否则难通过审核 |
| **AI辅助（校对/灵感/粗纲）** | 低风险 | 相对安全，但需如实标识 |
| **AI生成+深度人工改写** | 中风险 | 可行，但需投入大量修改时间 |
| **纯人工创作** | 无风险 | 推荐，签约率和流量最稳定 |

> **来源**：PHP中文网、今日头条多篇作者经验、龙空论坛讨论

## 五、番茄小说平台标准

### 5.1 签约节点（官方标准）
- **第一次申请**：2万字
- **第二次申请**：5万字
- **第三次申请**：8万字（失败则永久失去签约资格）
- **建议提交时机**：建议写到3万字再申请

> 注意：签约节点使用"字数"（非非空白字符），这是番茄官方标准。

### 5.2 章节长度建议
- 每章约2000字（约2100非空白字符）
- 每500字出现一次小转折
- 每章结尾卡在悬念点

### 5.3 质量指标
| 指标 | 达标值 | 优秀值 |
|------|--------|--------|
| 书架比 | ≥35% | ≥50% |
| 追更比 | ≥35% | ≥50% |
| 10万字完读率 | ≥15% | ≥20% |
| 第一章冲突 | 前500字内出现强冲突 | — |

### 5.4 时间节点
- **安全审核时间**：一般7天内
- **签约评估时间**：一般7天内，通常不超过2周

### 5.5 推荐机制（推流规则）

番茄小说推荐机制由实时数据驱动，核心看读者行为数据。

#### 5.5.1 推荐阶段划分

| 阶段 | 触发条件 | 时长 | 核心目标 |
|------|---------|------|---------|
| **验证期** | 8万字 | 约7天 | 找到最匹配的读者人群 |
| **首秀期** | 10万字+完读率≥15% | 约21天 | 进入核心流量池 |
| **长期推荐** | 首秀结束后 | 持续 | 靠读者行为滚动推荐 |

#### 5.5.2 验证期指标（7天定生死）

| 指标 | 要求 | 计算方式 |
|------|------|---------|
| **书架比** | ≥35% | 当日加书架人数÷当日阅读人数 |
| **追更比** | ≥35% | 当日追更人数÷当日阅读人数 |
| **断更惩罚** | 验证中断 | 断更一天，验证直接中断 |

> **注意**：2025年算法已提高要求，建议按≥35%准备。

#### 5.5.3 首秀期指标（21天黄金窗口）

| 指标 | 要求 | 说明 |
|------|------|------|
| **日更字数** | 6000字 | 每天必须稳定更新 |
| **10万字完读率** | ≥20% | 破20%才有机会进大池子 |
| **更新时段** | 避开22-24点 | 卡审高峰，影响数据 |
| **禁止操作** | 严禁大改 | 修改正文/换封面/重写简介会降权 |

**首秀判断标准**：
- 推荐期人数 **<300人** → 可以切书了
- 推荐期人数 **>500人** → 基本有首秀
- 推荐期人数 **300-500人** → 看完读率判断

#### 5.5.4 长期推荐指标（三率滚动）

| 指标 | 要求 | 说明 |
|------|------|------|
| **完读率** | 100章内≥5% | 全书读完人数÷首次阅读人数，≥5%拿星火奖励 |
| **追读率** | 持续稳定 | 每章阅读人数中下章继续读的比例 |
| **阅读时长** | 日均>60分钟 | 影响广告收益和推荐权重 |

#### 5.5.5 放量机制

番茄有两种放量方式：

1. **主动放量**（字数触发）
   - 8万字 → 进入验证期
   - 10万字 → 进入首秀期

2. **被动放量**（数据触发）
   - 某些数据达标后系统自动放量

#### 5.5.6 算法雷区（会导致断流）

| 操作 | 后果 |
|------|------|
| 同一设备登录多个作者账号 | 限流或清空数据 |
| 用小号刷阅读量 | 风控处罚 |
| 首秀期修改章节标题/删减情节 | 系统判定异常，降权 |
| 凌晨/深夜频繁更新 | 审核延迟+数据失真 |
| 未标注AI辅助内容 | 2025年9月起强制执行 |

#### 5.5.7 核心原则

> 番茄算法不看文笔和名气，只看读者行为数据——**点开、读完、加书架、追更、停留时长**。数据好就推，数据差就沉。

> **来源**：PHP中文网《番茄小说推荐机制是什么》、正软商城《番茄小说首秀推荐机制解析》、今日头条多篇作者经验分享

## 八、章节标题唯一性标准（强制执行）

### 核心规则

> **全书范围内，所有章节标题必须唯一，禁止重复。**

### 章节标题命名规范（强制执行）

> **核心原则**：章节标题必须描述本章的**具体事件或内容**，禁止使用叙事功能词作为标题。

**❌ 禁止使用的标题类型**：

| 禁止类型 | 错误示例 | 问题 |
|---------|---------|------|
| 叙事功能词 | 卷末高潮、卷末铺垫、卷末、卷首、开篇、过渡、转折 | 不是具体事件，读者无法产生兴趣 |
| **卷末/卷首类** | **模式匹配：卷末XX、卷首XX**（XX为任意词，包括但不限于：卷末收尾、卷末完结、卷末之战、卷末决战、卷末总结、卷末收官、卷末结尾、卷末冲突、卷末大事件、卷首要事、卷首开局） | **导航性词汇，破坏沉浸感，读者无需知道"卷末"结构** |
| 情绪描述词 | 压抑、爆发、爽点、高潮 | 太抽象，没有信息量 |
| 结构描述词 | 承上启下、衔接、收尾 | 纯功能性描述，无内容 |
| 重复标题 | 连续多章使用相同标题 | 读者无法区分章节 |
| 空泛标题 | 新的开始、新的挑战、新的敌人 | 没有具体信息 |
| **通用词标题** | **商行升级、四阶、天赋交易、修炼、突破** | **多章使用同一通用词，无法区分具体内容** |
| **规划编号词** | **伏笔1回收、伏笔2、爽点1、卡点3、高潮2、铺垫1、转折3、情节4、冲突1、事件5、回收1** | **创作规划术语+数字，暴露创作痕迹，破坏沉浸感** |

**✅ 正确的标题类型**：

| 正确类型 | 正确示例 | 优点 |
|---------|---------|------|
| 具体事件 | 赵家破产、商行升级、古武臣服 | 读者一眼知道本章内容 |
| 人物动作 | 林辰出手、苏晚跪求、李叔归顺 | 有画面感，引发好奇 |
| 悬念钩子 | 神秘买家现身、天道之门微启、暗中的敌人 | 制造期待感 |
| 关键物品 | 半块玉佩、商行来信、气运之眼 | 以物引事 |
| 场景转换 | 进京、酒吧开业、古武世界 | 标志格局变化 |

**标题长度规范（强制执行）**：
- **标准长度**：2-6个字（黄金区间）
- **最大长度**：不超过8个字（硬性上限）
- **推荐长度**：3-5个字（最佳可读性）

**标题唯一性规则**：
- 全书范围内，章节标题必须唯一
- 禁止任何位置出现完全重名标题，不限是否连续、不限是否跨卷
- 禁止使用仅替换"再""又""继续""新的"等弱区分词制造伪差异标题
- 禁止同一人物+同一动作组合反复作为标题主干
- 允许使用"上/下"表达单次事件拆分，但同一主干标题最多出现2次，且不得在其他章节再次复用
- 发现冲突时，禁止通过加序号、加副标题、临时改后缀的方式放行，必须回到卷纲层修复

**叙事功能词标题替换方法**：
1. 找到该章节的核心事件
2. 用"谁+做了什么"或"什么+发生了什么"格式替换
3. 替换示例：
   - "卷末高潮" → "赵家覆灭" / "古武世界臣服" / "天道之门开启"
   - "卷末铺垫" → "神秘来信" / "暗流涌动" / "暴风雨前的宁静"
   - "卷末" → "最终对决" / "尘埃落定" / "格局初定"
   - "卷末收尾" → "京城暗流" / "新的征途" / "余波未平"
   - "卷末完结" → "告别旧城" / "踏上征程" / "风云落幕"
   - "卷首" → "初入京城" / "风起云涌" / "暗流初现"
   - "新的挑战" → "武天行的试探" / "京城豪门出手"
   - "伏笔1回收" → "玉佩显威" / "血誓应验" / "族纹觉醒"
   - "爽点1" → "打脸李少" / "境界突破" / "拍卖夺宝"
   - "卡点3" → "赵家围堵" / "功力被封" / "身世谜团"
   - "铺垫1" → "神秘来信" / "暗流涌动" / "风云将起"

**标题长度检查方法**：
```
步骤1：提取章节标题（去掉"第XXX章-"前缀）
步骤2：计算标题字数（汉字算1字，英文/数字算0.5字）
步骤3：判断是否符合规范
       - 2-6字：✅ 符合标准
       - 7-8字：可接受，但建议精简
       - >8字：❌ 必须修改
步骤4：对超长标题进行精简
       - 删除修饰词（"的""之"等）
       - 删除冗余描述
       - 保留核心事件关键词
```

**标题精简示例**：

| 原标题（冗长） | 精简后 | 精简方法 |
|--------------|--------|---------|
| 林辰被公司辞退的那一天 | 被辞退 | 删除人物名+时间修饰 |
| 神秘买家终于现身了 | 神秘买家 | 删除"终于""了" |

| 检查维度 | 要求 | 说明 |


### 标题冲突检测方法

```
步骤1：遍历全书所有章纲文件（05-章纲/NN-第X卷-卷名/第XXX章-标题.md）
步骤2：提取所有章节标题（去掉"第XXX章-"前缀）
步骤3：建立标题→章节号映射表
步骤4：检测完全重名、主干重复、人物动作重复、弱区分词伪差异
步骤5：生成"标题冲突检查表"
步骤6：如发现任一冲突，标记为阻塞问题并回退卷纲层修复
```

### 标题冲突检查表统一格式

`| 序号 | 标题 | 来源位置 | 冲突对象 | 问题类型 | 处理结论 |`

**填写要求**：
- 来源位置：填写章节号或文件位置
- 冲突对象：无冲突时填写`无`
- 问题类型：只能使用固定枚举
- 处理结论：只能使用固定枚举
- 禁止只写"已检查通过"，必须显式输出整张检查表

**问题类型固定枚举**：
- `通过`
- `完全重复`
- `主干重复`
- `人物动作重复`
- `伪差异`
- `禁用词`

**处理结论固定枚举**：
- `保留`
- `重写标题`
- `回退卷纲层修复`
- `回退章纲层修复`
- `阻塞待修`

### 标题冲突严重级别

| 级别 | 场景 | 处理方式 |
|------|------|---------|
| 严重 | 全书范围内标题完全重复 | 立即阻塞，回退卷纲层修复 |
| 严重 | 标题主干重复、人物动作重复、弱区分词伪差异 | 立即阻塞，回退卷纲层修复 |
| 严重 | 标题含禁用词、导航词、规划编号词 | 立即阻塞，重写标题后复查 |
| 轻微 | 标题语义接近但未构成重复主干 | 可选优化 |

### 标题冲突修复策略

**策略1：回到核心事件重拟标题（推荐）**
```
原标题：决战
修改方式：根据本章具体情节重新拟定标题，避免使用导航类字眼
示例：决战 → 皇城之战 / 决战 → 巅峰对决 / 决战 → 最终审判
```

**策略2：改写为人物动作或关键物品标题**
```
原标题：修炼
修改后：修炼 → 林辰破境 / 修炼 → 丹炉异响 / 修炼 → 夜探药阁
```

**策略3：单次事件拆分为上/下（仅限真实拆分）**
```
原标题：赵家崩盘
允许写法：赵家崩盘（上）/ 赵家崩盘（下）
限制：仅限同一事件拆分，最多2章，且不得在其他章节再次复用该主干
```

**禁止性修复方式**
```
- 禁止添加副标题放行：决战：皇城之巅
- 禁止添加序号放行：修炼（一）/ 修炼（二）/ 修炼（三）
- 禁止临时补弱区分词：再次交易 / 又一次交易 / 新的交易
```

### 卷定位规则（强制执行）

> 当需要根据章节号确定所属卷时，**必须按以下步骤执行**：

```
步骤1：读取总纲（01-总纲/总纲.md），获取分卷规划表
步骤2：从分卷规划表中提取每卷的卷编号、卷名、章节范围
```

## 十三、使用规范

1. **引用方式**：技能执行时首先读取本文件
2. **冲突处理**：技能内部数值与本文件冲突时，以本文件为准
3. **更新流程**：修改本文件需同步更新所有引用技能
4. **验证要求**：审查技能需检查输出是否符合本文件标准
