# 卷纲章节卡片表格模板

> **区分说明（强制）**：章节卡片表格 vs 章纲（必须区分）
>
> | 维度 | 章节卡片表格（本模板） | 章纲 |
> |------|------------------------|------|
> | 创建技能 | novel-outline-designer | novel-chapter-outline-creator |
> | 保存位置 | `02-卷纲/NN-第X卷-卷名.md` 内的表格 | `05-章纲/NN-第X卷-卷名/` |
> | 字数要求 | **每行50-100字符** | 250-350字符（多段落） |
> | 用途 | 卷级规划，快速浏览章节走向 | 正文写作指导，详细情节分解 |
> | 内容深度 | 核心事件+衔接+爽点+卡点 | 完整情节分解+对话示例+场景细节 |
> | 格式 | **表格行** | 多段落，含对话和场景 |
> | 创建时机 | 大纲阶段 | 章纲阶段 |
>
> ❌ **常见错误**：把章节卡片写成章纲（写了3000字符）→ 章节卡片只需一行
> ❌ **常见错误**：把章节卡片写成正文（写了完整对话和场景）→ 章节卡片不需要对话

## 表格格式规范

```
| 章节号 | 标题 | 衔接信息 | 核心事件 | 人物状态 | 爽点设计 | 卡点设计 |
|--------|------|----------|----------|----------|----------|----------|
| 第XXX章 | 标题 | 承接：xxx/开启：xxx | 核心事件描述 | 人物状态 | 爽点描述 | 卡点描述 |
```

> **保存规则（强制）**：表格直接包含在卷纲文件中，不需要创建独立文件。

## 章节标题来源与提取规则（关键关联机制）

> **核心原则**：章节标题必须从"章节分段总览"的"核心内容"字段中提取，确保两者一致。

### 标题来源流程

```
┌─────────────────────────────────────────────────────────┐
│  章节标题生成流程（强制执行）                              │
├─────────────────────────────────────────────────────────┤
│ 步骤1：读取章节分段总览                                    │
│     - 从卷纲文件中获取"章节分段总览"表格                  │
│     - 确定当前章节所属段落                                │
│                                                          │
│ 步骤2：提取关键事件列表                                    │
│     - 从该段落的"核心内容"字段提取关键事件                │
│     - 按逗号/顿号分解为多个事件                          │
│     - 示例："主角入京，遭遇打压，结识李叔"                │
│       → ["主角入京", "遭遇打压", "结识李叔"]             │
│                                                          │
│ 步骤3：映射到章节标题                                      │
│     - 当前章节在该段落中的序号 → 对应的关键事件           │
│     - 示例：第2章在第一段（第1-5章），序号2              │
│       → 标题 = "遭遇打压"                                │
│                                                          │
│ 步骤4：标题精简与规范化                                    │
│     - 长度控制：2-6字（标准），最多8字                   │
│     - 删除修饰词（"的""之""终于""了"等）                │
│     - 确保是具体事件（非叙事功能词）                      │
│                                                          │
│ 步骤5：标题去重检查                                        │
│     - 与本卷已有标题逐项比对                              │
│     - 排除完全重复、主干重复、人物动作重复                │
│     - 排除仅靠"再""又""继续"等弱区分词制造的伪差异      │
│                                                          │
│ 一致性验证：                                             │
│     - 章节标题是否来自对应段落的关键事件？                │
│     - ❌ 不是 → 必须从段落关键事件中选取                  │
│     - 关键事件数量是否等于该段章节数？                    │
│     - ❌ 不相等 → 补充或精简关键事件                      │
└─────────────────────────────────────────────────────────┘
```

### 标题提取示例

**章节分段总览**：
| 段落 | 章节范围 | 核心内容 |
|------|----------|----------|
| 第一段 | 第1-5章 | 主角入京，遭遇打压，结识李叔，获得情报，首次出手 |

**生成的章节标题**：
| 章节号 | 标题 | 来源 |
|--------|------|------|
| 第001章 | 入京 | 第一段关键事件1 |
| 第002章 | 遭遇打压 | 第一段关键事件2 |
| 第003章 | 结识李叔 | 第一段关键事件3 |
| 第004章 | 获得情报 | 第一段关键事件4 |
| 第005章 | 首次出手 | 第一段关键事件5 |

### 常见错误

| 错误类型 | 错误示例 | 正确做法 |
|---------|---------|---------|
| 标题与段落无关 | 第一段核心内容："主角入京..."，第2章标题："商行升级" | 标题应来自段落关键事件 |
| 关键事件数量不足 | 第一段5章，核心内容只写"主角入京"（1个事件） | 补充为"主角入京，遭遇打压，结识李叔，获得情报，首次出手" |
| 使用叙事功能词 | 标题："卷末高潮" | 替换为具体事件："玄清子命格破碎" |

### 章节标题长度规范（强制执行）

| 规范项 | 要求 |
|--------|------|
| **标准长度** | 2-6个字（黄金区间） |
| **最大长度** | 不超过8个字（硬性上限） |
| **推荐长度** | 3-5个字（最佳可读性） |
| **禁止** | 超过8个字的冗长标题 |

### 章节标题去重规则（强制执行）

| 检查项 | 通过标准 |
|--------|----------|
| **完全重复** | 同卷内相同标题只能出现1次 |
| **主干重复** | 同一标题主干不得在多章复用 |
| **人物动作重复** | 同一人物+同一动作组合不得重复使用 |
| **伪差异标题** | 仅靠"再""又""继续""新的"等弱区分词，不算新标题 |
| **上下拆分** | 仅允许单次事件使用"上/下"，且同主干最多2章 |

> **强制动作**：章节卡片表格完成后，必须输出"标题唯一性检查表"。
> **统一格式**：`| 序号 | 标题 | 来源位置 | 冲突对象 | 问题类型 | 处理结论 |`
> **问题类型固定枚举**：`通过 / 完全重复 / 主干重复 / 人物动作重复 / 伪差异 / 禁用词`
> **处理结论固定枚举**：`保留 / 重写标题 / 回退卷纲层修复 / 回退章纲层修复 / 阻塞待修`
> **填写要求**：来源位置填写章节号；无冲突行统一写为`无 | 通过 | 保留`。
> **阻塞规则**：发现重名或高度相似标题，必须先改标题，再继续后续验证。

### 章节标题禁用词检查（强制执行）

> **标题要求（强制）**：章节标题必须描述具体事件，禁止使用以下词汇。

| 禁止类型 | 禁用词汇 | 问题 |
|---------|---------|------|
| **卷/部结构词** | **模式匹配：第X卷、卷X、第X部**（X为任意数字） | 结构导航词，非具体事件 |
| | 示例：第一卷、第八卷、第十卷、卷一、卷八、第一部、第三部 | 结构导航词，非具体事件 |
| | 卷末、卷首、卷尾、下一卷、本卷、上卷、下卷、前卷、后卷 | 导航性词汇，非具体事件 |
| **章节导航词** | 下一章、上一章、本章、下章、前章、章节回顾 | 导航性词汇，非具体事件 |
| **叙事功能词** | 卷末高潮、卷末铺垫、开篇、过渡、转折 | 不是具体事件 |
| **情绪描述词** | 压抑、爆发、爽点、高潮、承上启下、衔接、收尾 | 太抽象，无信息量 |
| **空泛标题** | 新的开始、新的挑战、新的敌人 | 没有具体信息 |
| **规划性词汇** | 根据大纲、按照计划、伏笔回收、埋下伏笔 | meta词汇，暴露创作痕迹 |

> **完整禁用词列表引用**：`统一标准.md` 第1.5.1节

**检查机制（模式匹配）**：
```
检测规则：
1. 匹配"第X卷"模式（X为一/二/三/四/五/六/七/八/九/十/百等中文数字）
   → 匹配到 → 禁用词，必须替换
2. 匹配"卷X"模式（X为中文数字）
   → 匹配到 → 禁用词，必须替换
3. 匹配"第X部"模式（X为中文数字）
   → 匹配到 → 禁用词，必须替换
4. 检测固定禁用词（卷末、卷首、卷尾等）
   → 匹配到 → 禁用词，必须替换
```

**检查示例**：
- ❌ `第三卷` → 匹配"第X卷"模式 → 禁用词
- ❌ `第八卷` → 匹配"第X卷"模式 → 禁用词
- ❌ `卷五` → 匹配"卷X"模式 → 禁用词
- ❌ `第二部` → 匹配"第X部"模式 → 禁用词
- ✅ `皇城之战` → 无匹配 → 通过
- ✅ `分手觉醒` → 无匹配 → 通过

## 章节卡片内容格式（一行式）

每张章节卡片只写**一行**，用管道符 `|` 分隔各字段：

```
第XXX章 | 标题 | 承接：xxx | 开启：xxx | 事件：xxx | 人物：xxx | 爽点：xxx | 卡点：xxx
```

### 字段说明

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| 章节号 | ✅ | 第XXX章 | 第001章 |
| 标题 | ✅ | 2-6字，具体事件 | 分手觉醒 |
| 承接 | ✅ | 第1章写"开篇"，后续写具体内容 | 开篇 |
| 开启 | ✅ | 最后一章写"卷末完结"，其他写开启内容 | 开启：初次交易 |
| 事件 | ✅ | 一句话概括核心事件（10-30字） | 林辰被分手后觉醒商行，交易赵浩霉运获10万 |
| 人物 | ✅ | 主角状态（位置/情绪/目标） | 绝望→觉醒，位置-商业街 |
| 爽点 | ✅ | 类型+内容（10-20字） | 打脸：赵浩被广告牌砸 |
| 卡点 | ✅ | 章节结尾钩子（10-20字） | 10万到账，"谁是废物？" |

### 伏笔（可选）

如有伏笔，在卡片末尾追加：`| 伏笔：xxx（第X章回收）`

## 禁止缩略（强制）

> - ❌ 禁止将多章卡片合并到一行中 → 每章必须是独立的一行
> - ❌ 禁止只写章节范围（如"第1-10章：xxx"）→ 每章都必须单独创建一行
> - ❌ 禁止表格行不完整（省略中间章节）→ 必须列出所有章节
> - ❌ 禁止表格行内容过少（<50字符）→ 每行必须完整填写
> - ✅ 正确做法：每章在章节卡片表格中添加一行

## 三大常见问题及避免方法（关键新增）

> **以下三个问题是卷纲创建中最常见的错误，必须严格避免！**

### 问题一：章节内容重复

**问题描述**：不同章节的核心事件或章节标题相同或高度相似

**错误示例**：
```
第005章标题：首次交易
第012章标题：再次交易  ← 主干重复，仍然不合格！
第005章核心事件：林辰交易赵浩霉运获利
第012章核心事件：林辰交易赵浩霉运获利  ← 重复！
```

**正确做法**：
```
第005章标题：霉运成交
第012章标题：新规浮现  ← 标题与事件都已区分
第005章核心事件：林辰首次交易赵浩霉运，获10万
第012章核心事件：林辰再次交易赵浩，发现新规则
```

**避免方法**：
- ✅ 每章核心事件必须独特，不能与之前章节重复
- ✅ 每章标题也必须独特，不能只靠"首次""再次""又一次"制造伪差异
- ✅ 创建时对比之前所有章节的核心事件与标题，确保无重复

---

### 问题二：链接不上

**问题描述**：相邻章节的衔接信息不对应，导致情节断裂

**错误示例**：
```
第005章 开启下章：赵浩倒霉事件
第006章 承接上章：林辰获得10万  ← 不对应！
```

**正确做法**：
```
第005章 开启下章：赵浩开始倒霉
第006章 承接上章：赵浩倒霉开始  ← 对应！
```

**避免方法**：
- ✅ 第N章的"开启下章"必须与第N+1章的"承接上章"描述同一事件/状态
- ✅ 创建每章时，必须查看上一章的"开启下章"字段
- ✅ 衔接信息使用相同或相近的关键词，确保读者能识别

---

### 问题三：章节内容提前

**问题描述**：事件在错误的章节提前出现，破坏故事顺序

**错误示例**：
```
卷纲规划：林辰先觉醒商行 → 首次交易 → 商行升级
第003章核心事件：商行升级  ← 提前！应先有首次交易
```

**正确做法**：
```
第001章核心事件：林辰觉醒商行
第002章核心事件：林辰首次交易
第010章核心事件：商行升级  ← 顺序正确
```

**避免方法**：
- ✅ 创建章节卡片前，先确认卷纲中的事件顺序链
- ✅ 检查当前章节是否已具备发生该事件的前提条件
- ✅ 如事件需要提前，必须同步修改卷纲规划

## 实时顺序校验机制（关键新增，防止内容超前）

> **核心原则**：每填写一章，必须实时校验事件顺序，不能等到最后验证。

### 前置条件

**在填写章节卡片表格前，必须先完成**：
1. 建立事件顺序链表格（见SKILL.md步骤2.4）
2. 事件顺序链表格格式：`| 序号 | 事件名称 | 前置事件 | 最早章节 | 说明 |`

### 实时校验流程

```
┌─────────────────────────────────────────────────────────┐
│  🔒 每填写一章必须执行的实时校验                           │
├─────────────────────────────────────────────────────────┤
│ 步骤1：提取当前章节的核心事件                              │
│     - 从章节卡片的"核心事件"字段提取事件关键词            │
│                                                          │
│ 步骤2：在事件顺序链中查找该事件                            │
│     - 在事件顺序链表格中搜索该事件                        │
│     - 获取该事件的"前置事件"和"最早章节"                  │
│                                                          │
│ 步骤3：校验事件位置                                       │
│     ├── 校验A：当前章节 ≥ 最早章节？                      │
│     │   → ❌ 当前章节 < 最早章节 → 事件超前，阻塞        │
│     │                                                    │
│     └── 校验B：前置事件是否已出现？                       │
│         → 检查前置事件是否在之前的章节中已出现            │
│         → ❌ 前置事件未出现 → 事件超前，阻塞             │
│                                                          │
│ 步骤4：处理超前问题                                       │
│     → ❌ 发现事件超前 → 立即阻塞                         │
│     → 选择处理方式：                                      │
│       - 方式A：将该事件移到正确的章节                     │
│       - 方式B：修改事件顺序链（如确实需要提前）           │
│     → 修复后重新校验，通过后才能继续填写下一章            │
└─────────────────────────────────────────────────────────┘
```

### 校验示例

**事件顺序链表格**：
| 序号 | 事件名称 | 前置事件 | 最早章节 | 说明 |
|------|----------|----------|----------|------|
| 1 | 觉醒商行 | - | 第1章 | 开篇事件 |
| 2 | 首次交易 | 觉醒商行 | 第2章 | 需要先觉醒 |
| 3 | 商行升级 | 首次交易 | 第10章 | 需要交易经验 |

**填写第3章时的校验**：
```
当前章节：第003章
核心事件：商行升级

校验A：第3章 ≥ 第10章？ → ❌ 否 → 事件超前！
校验B：前置事件"首次交易"是否已出现？
       → 检查第1-2章，发现"首次交易"在第2章 → ✅ 已出现

结论：事件超前，必须调整！
处理：将"商行升级"移到第10章，第3章改为其他事件
```
