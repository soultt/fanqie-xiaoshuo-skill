# 章纲审查执行流程

> 本文件由 `novel-outline-vetter/SKILL.md` 引用，定义章纲审查的完整执行流程。

---

## 阻塞式审查执行机制（强制）

**每个审查节点必须完成才能进入下一个节点，不可跳过任何步骤。**

### 执行规则（强制）

- **规则1**：必须按顺序执行，不可跳过任何审查节点
- **规则2**：每个节点必须输出检查结果（通过/问题/失败）
- **规则3**：优先审查发现严重冲突 → 强制阻塞，必须修复后重查
- **规则4**：每级审查完成后必须勾选确认，才能进入下一级
- **规则5**：最终报告必须包含所有审查节点及报告生成的结果

### 审查节点完成确认清单

**每完成一个节点，必须勾选确认**：
- [ ] **节点0**：优先审查（前后章节冲突7项）已完成
- [ ] **节点1**：一级审查（大纲符合性5项）已完成
- [ ] **节点2**：章纲约束清单一致性审查（6项）已完成
- [ ] **节点3**：二级审查（结构完整性4项）已完成
- [ ] **节点4**：三级审查（剧情质量3项）已完成
- [ ] **节点5**：四级审查（文笔规范4项）已完成
- [ ] **节点6**：生成审查报告已完成

**未全部勾选 → 审查报告不完整，不得输出**

### 阻塞触发条件

> **阻塞说明（强制）**：所有触发条件均为强制阻塞，不得以"警告"为由跳过。

| 触发条件 | 阻塞级别 | 处理方式 |
|----------|----------|----------|
| 优先审查发现严重冲突（P0） | 强制阻塞 | 立即停止，修复后从节点0重查 |
| 章纲约束清单不一致 | 强制阻塞 | 立即停止，修正后重查 |
| 核心事件与卷纲不符 | 强制阻塞 | 立即停止，修正后重查 |
| 章节标题存在重名/高度相似冲突 | 强制阻塞 | 立即停止，返回卷纲层修复后重查 |
| 其他审查发现严重问题 | 强制阻塞 | 立即停止，修复后重查 |
| 任何节点未执行 | 强制阻塞 | 补全后才能输出报告 |
| 发现问题未修复 | 强制阻塞 | 修复后才能继续 |

> **审查开始确认（强制）**：
> - [ ] 我已阅读并理解阻塞式审查执行规则
> - [ ] 我将按顺序执行所有审查节点，不跳过任何节点
> - [ ] 每个节点完成后我将勾选确认清单
> - [ ] 发现阻塞问题时我将立即停止，不输出不完整报告
> - [ ] 最终报告将包含所有节点的审查结果
>
> **未全部勾选确认 → 不得开始审查**

## 步骤一：确认审查范围

- 单章审查 or 批量审查
- 确定章节号和所属卷

**步骤完成确认**：[ ] 步骤一（确认审查范围）已完成

---

## 步骤二：读取审查依据

- 读取总纲（整体规划）
- 读取卷纲（卷级任务）
- 读取章纲（审查对象）
- 读取人物设定（人设一致性）
- **读取章纲约束清单（强制，一致性审查）**

**步骤完成确认**：[ ] 步骤二（读取审查依据）已完成

---

## 步骤三：优先审查（前后章节冲突）

- 读取前章章纲
- 检查7项冲突：
  1. 人物状态冲突
  2. 时间线冲突
  3. 地点空间冲突
  4. 物品道具冲突
  5. 人物关系冲突
  6. 剧情逻辑冲突
  7. 能力设定冲突

**节点完成确认**：[ ] 节点0：优先审查已完成

**发现阻塞问题 → 停止执行，修复后重新审查**

---

## 步骤四：一级审查（大纲符合性）

- 对照卷纲检查5项符合性：
  1. 核心事件与卷纲一致
  2. 四部分结构完整
  3. 爽点类型和强度与卷纲一致
  4. 伏笔与卷纲一致
  5. 卡点与卷纲一致

**节点完成确认**：[ ] 节点1：一级审查已完成

---

## 步骤五：章纲约束清单一致性审查

> **审查维度说明**：此审查维度用于确保章纲与章纲约束清单保持一致。

### 审查流程

```
步骤1：读取章纲约束清单
    路径：08-约束清单/章纲约束/NN-第X卷-卷名/第XXX章-约束清单.md

步骤2：验证文件存在？
    存在 → 继续步骤3
    不存在 → 标记为 P0 级问题："章纲约束清单缺失"

步骤3：逐项对比章纲与章纲约束清单
    对比项：核心事件、爽点设计、伏笔规划、卡点设计、人物状态、禁止事项

步骤4：生成一致性审查结果
    一致 → 标记为"通过"
    不一致 → 标记为 P0 级问题，详细说明差异
```

### 一致性审查清单

| 检查项 | 章纲内容 | 章纲约束清单内容 | 一致性 |
|--------|----------|-----------------|--------|
| 核心事件 | [提取] | [提取] | ☑/☒ |
| 爽点设计 | [提取] | [提取] | ☑/☒ |
| 伏笔规划 | [提取] | [提取] | ☑/☒ |
| 卡点设计 | [提取] | [提取] | ☑/☒ |
| 人物状态 | [提取] | [提取] | ☑/☒ |
| 禁止事项 | [检查] | [检查] | ☑/☒ |

**一致性检查处理规则**：
- 章纲约束清单是旧版本 → "章纲约束清单过期，需同步更新"
- 章纲违反约束 → "章纲违反约束，需修改章纲"

**节点完成确认**：[ ] 节点2：章纲约束清单一致性审查已完成

**节点完成确认**：[ ] 节点3：二级审查已完成

- 输出到 `07-审查报告/章纲审查/第XXX章-审查报告.md`

**节点完成确认**：[ ] 节点6：生成审查报告已完成

## 步骤十：审查后章纲约束清单同步

**同步更新要求（强制）**：如审查结果要求修改章纲，修改完成后必须同步更新章纲约束清单。

```
修改章纲后同步流程：
1. 确认章纲已修改
2. 检查章纲约束清单本身是否可用
   ├── 章纲约束清单正常 → 重新生成章纲约束清单（同步更新）
   └── 章纲约束清单有问题 → 重新生成章纲约束清单
3. 保存到：08-约束清单/章纲约束/NN-第X卷-卷名/第XXX章-约束清单.md
4. 验证章纲约束清单与修改后章纲一致
5. 此步骤不可跳过
```

---

## 审查注意事项

1. **章纲约束清单是审查依据**：审查章纲时必须同时读取章纲约束清单
2. **修改章纲后必须同步章纲约束清单**：审查导致章纲修改时，章纲约束清单必须同步更新
3. **卷纲优先原则**：如发现章纲与卷纲不一致，必须以卷纲为准
4. **前章正文优先**：如发现章纲与前章正文结尾不一致，以前章正文为准
