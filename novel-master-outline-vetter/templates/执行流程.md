# 大纲审查执行流程

> 本文件由 `novel-master-outline-vetter/SKILL.md` 引用，定义大纲审查的完整执行流程。

---

## 阻塞式审查执行机制（强制）

**每个审查节点必须完成才能进入下一个节点，不可跳过任何步骤。**

### 执行规则（强制）

- **规则1**：必须按顺序执行，不可跳过任何审查节点
- **规则2**：每个节点必须输出检查结果（通过/问题/失败）
- **规则3**：优先审查发现严重冲突 → 强制阻塞，必须修复后重查
- **规则4**：每级审查完成后必须勾选确认，才能进入下一级
- **规则5**：最终报告必须包含所有审查节点及报告生成的结果

### 审查节点完成确认清单

**每完成一个节点，必须勾选确认**：
- [ ] **节点0**：阶段零确认（阻塞式审查机制已启用）
- [ ] **节点1**：优先审查（冲突审查7项）
- [ ] **节点2**：一级审查（总纲质量5项）
- [ ] **节点3**：二级审查（卷纲质量8项）
- [ ] **节点4**：三级审查（逻辑一致性4项）
- [ ] **节点5**：四级审查（签约标准）
- [ ] **节点6**：生成审查报告

**未全部勾选 → 审查报告不完整，不得输出**

### 阻塞触发条件

> **阻塞说明（强制）**：所有触发条件均为强制阻塞，不得以"警告"为由跳过。

| 触发条件 | 阻塞级别 | 处理方式 |
|----------|----------|----------|
| 优先审查发现严重冲突（P0） | 强制阻塞 | 立即停止，修复后从节点0重查 |
| 卷间衔接冲突 | 强制阻塞 | 立即停止，修正后重查 |
| 人物成长轨迹冲突 | 强制阻塞 | 立即停止，修正后重查 |
| 时间线规划冲突 | 强制阻塞 | 立即停止，修正后重查 |
| 其他审查发现严重问题 | 强制阻塞 | 立即停止，修复后重查 |
| **卷纲不完整（行数<150或必须项缺失）** | **强制阻塞** | **立即停止，补充后重审** |
| **章节标题质量问题（叙事功能词/重名/高度相似）** | **强制阻塞** | **立即停止，返回卷纲层修复后重审** |
| 任何节点未执行 | 强制阻塞 | 补全后才能输出报告 |
| 发现问题未修复 | 强制阻塞 | 修复后才能继续 |

> **完整阻塞触发条件**：详见 [审查验证规范 - 阻塞触发条件](./审查验证规范.md#66-阻塞触发条件强制)

### 审查完成判定

全部4个节点已完成 → 检查是否有阻塞问题 → 有则修复后重审，无则输出报告。

7. **节点5：四级审查（签约标准）** → 勾选确认

**节点完成确认**：
- [ ] 节点1：优先审查已完成
- [ ] 节点2：一级审查已完成
- [ ] 节点3：二级审查已完成
- [ ] 节点4：三级审查已完成
- [ ] 节点5：四级审查已完成

### 大卷纲分段审查机制（关键）

> 当卷纲章节数超过30章时，必须使用分段审查机制，避免因token限制导致审查不完整。

**模板引用**：详见 [分段审查规范](./分段审查规范.md)

**触发条件速查**：
| 卷纲章节数 | 审查模式 |
|-----------|---------|
| ≤30章 | 全量审查 |
| 31-60章 | 分2段 |
| 61-100章 | 分3段 |
| >100章 | 分4+段 |

**节点完成确认**：[ ] 节点6：生成审查报告已完成

### 修复技能调用映射

> 审查技能只负责发现问题，修复必须调用对应技能完成，不得自行修改。

**模板引用**：详见 [修复映射表](./修复映射表.md)

**映射概要**：
- 节点1-3 问题 → 调用 `novel-outline-designer` 修复
- 节点4 签约问题 → 调用 `novel-outline-designer` 或 `fanqie-contract-evaluator`
- 修复完成后必须重新执行完整审查流程

## 阶段四：审查后约束清单同步检查

> **同步检查说明（强制）**：大纲审查修改可能影响已有章纲约束清单与正文约束清单的准确性。

10. **检查约束清单一致性**
    - 如大纲审查未修改大纲 → 相关约束清单无需变更，跳过此步骤
    - 如大纲审查修改了总纲或卷纲 → 检查已生成的章纲约束清单与正文约束清单是否受影响

11. **约束清单同步处理**
    - 相关约束清单与修改后大纲一致 → 无需更新
    - 相关约束清单与修改后大纲不一致 → 通知相关技能（`novel-outline-vetter`、`novel-chapter-writer`）重新生成受影响的约束清单
    - 相关约束清单本身有问题（过期、损坏等）→ 重新生成对应的约束清单

---

## 批量审查功能

**适用场景**：审查整本书的大纲体系

**审查重点**：总纲质量 → 各卷纲质量 → 大纲体系一致性 → 签约标准

**输出**：总纲审查报告 + 各卷纲审查报告 + 整体评估报告 + 签约可能性评估

---

**记住大纲审查的核心目的**：
> "大纲是建筑的蓝图，审查是为了确保蓝图没有设计缺陷。好的大纲审查能提前发现结构性问题，避免写到后期才发现无法收场。"
