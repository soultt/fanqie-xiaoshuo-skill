## 核心定位

基于番茄小说签约标准和爆款作品结构，对总纲和卷纲进行全面审查，确保大纲质量达到签约要求，发现并修正结构、逻辑、节奏等问题。

## 审查验证机制

> **核心要求**：审查结论必须基于当前文件内容，不得只凭口头判断或历史记忆下结论。

**执行要求**：
- ✅ 每个检查项都要基于实际文件内容核对
- ✅ 审查结论要给出对应的文件依据
- ✅ 禁止仅口头声明"通过"或"无问题"

> **完整规范**：详见 [审查验证规范](./templates/审查验证规范.md)

### 验证规则速查

| 规则 | 说明 |
|------|------|
| 规则1 | 每个检查项都必须有对应的文件依据 |
| 规则2 | 审查输出必须体现验证依据 |
| 规则3 | 禁止仅口头声明"已检查"或"通过" |
| 规则4 | 禁止以任何理由跳过检查项 |
| 规则5 | 禁止抽查部分内容而非全量验证 |
| 规则6 | 每次审查都应重新核对当前文件内容 |
| 规则7 | 禁止使用"之前读取""我记得"等依赖记忆的表述 |
| 规则8 | 记忆与文件冲突时，以文件为准 |

## 审查维度体系

> **完整检查项和评估标准**：详见 [审查维度详解](./templates/审查维度详解.md)
>
> **数值标准（爽点/伏笔/签约节点）**：详见 [大纲审查标准速查](./templates/大纲审查标准速查.md)

### 优先审查：前后章节冲突（最高优先级）

> **审查说明（强制）**：大纲阶段的冲突审查是整个创作流程的第一道防线，必须在所有其他审查之前执行。

**审查子项**：卷间衔接冲突、人物成长轨迹冲突、时间线规划冲突、势力发展冲突、主线推进冲突、爽点分布冲突、伏笔规划冲突（共7项）

---

### 一级审查：总纲质量审查（P1）

**审查子项**：核心钩子审查、主角设定审查、主线脉络审查、分卷规划审查、爽点分布审查

---

### 二级审查：卷纲质量审查（P2）

**审查子项**：
- 卷核心任务审查
- 卷情节结构审查（开端/发展/高潮/结局四部分）
- 人物出场审查（含反派独立性审查）
- 爽点节奏审查
- 伏笔埋设审查
- **卷纲完整性审查（强制）**：行数≥150、必须项全部填写
- **章节标题质量审查（强制）**：禁止叙事功能词/通用词/重名/高度相似
- **章节卡片表格详细度审查（关键）**

> **章节标题冲突处理原则（强制）**：发现冲突时禁止以"加序号/改副标题"在审查报告中放行，必须回到卷纲层修复。
> **问题类型固定枚举**：`通过 / 完全重复 / 主干重复 / 人物动作重复 / 伪差异 / 禁用词`
> **处理结论固定枚举**：`保留 / 重写标题 / 回退卷纲层修复 / 回退章纲层修复 / 阻塞待修`
> **输出要求（强制）**：审查报告必须显式粘贴"标题冲突审查表"，禁止只写"已检查通过"。

> **章节卡片审查**：详见 [章节卡片审查规范](./templates/章节卡片审查规范.md) —— 每章规划合计≥50字符，核心事件≥20字符，爽点/卡点各≥10字符。

---

### 三级审查：逻辑一致性审查（P3）

**审查子项**：总纲与卷纲一致性、卷纲与卷纲一致性、大纲与人物设定一致性、大纲与世界观一致性

---

### 四级审查：签约标准审查（P4）

**审查子项**：开篇吸引力审查（黄金开篇法则）、节奏把控审查、商业价值审查

## 执行流程

> **完整执行流程**：见 [执行流程](./templates/执行流程.md)

### 执行概述

1. **阶段零**：启用阻塞式审查机制 → 确认所有规则
2. **阶段一**：确定审查范围 + 获取审查依据
3. **阶段二**：按序执行审查节点（优先审查 → 一级 → 二级 → 三级 → 四级）
   - 大卷纲（>30章）启用 [分段审查机制](./templates/分段审查规范.md)
4. **阶段三**：生成审查报告 → 保存到 `07-审查报告/大纲审查/`
5. **阶段四**：审查后约束清单同步检查

> **阻塞机制**：所有节点必须按序执行，不可跳过。任一阻塞条件触发 → 立即停止 → 修复后重审。
